# Data Product: Statistik-RA (Swiss OKP Risk Equalization Statistics)

## 1. Purpose

This data product consolidates the annual Risikoausgleich (RA) statistics
published by the Swiss Federal Office of Public Health (BAG) into analysis-ready
normalized tables. It supports two uses in this project:

1. **Calibration**: grounding the cost parameters in `code/simulation.py` in
   empirically observed Swiss cost levels, age-sex effects, and PCG cost
   increments.
2. **Validation**: comparing simulation outputs against observed BAG metrics
   such as insurer-level cost distribution, canton-level risk composition,
   and average costs per risk cell.

## 3. Schema Eras

The BAG changed the workbook structure three times, aligned to Swiss RA reform
phases. **Parsers and output tables are era-specific.**

| Era label | Years | RA phase | Observable dimensions | Schema family |
|-----------|-------|----------|-----------------------|---------------|
| `phase1_legacy` | 1996–2011 | Phase 1 | Age, sex | Wide pivoted: cantons as rows, age-sex groups as columns. Multi-sheet. |
| `phase2_transition` | 2012–2019 | Phase 2 | Age, sex, prior hospitalisation | Long format: one row per canton × age band × sex × hospitalisation. Single sheet `Daten YYYY`. |
| `phase3_modern` | 2020–2024 | Phase 3 | Age, sex, prior hosp., 22 PCGs | Multi-sheet: national summary with PCG columns, separate canton-risk-group sheet, PCG matrix, comorbidity matrix. |

---

## 4. Revision Policy

Several years have multiple published files, identified by a numeric suffix in
the filename (e.g., `Statistik-RA-2022-1.xlsx` and `Statistik-RA-2022-2.xlsx`).

**Canonical selection rule**: the file with the highest revision number for a
given year is treated as canonical (the authoritative source for that year).
Lower-revision files are retained in `data/statistik-ra/` and documented in
`output/data/source_manifest.csv` with `is_canonical = False`.

Rationale: BAG typically issues higher-numbered revisions to correct errors or
apply final adjustments after preliminary publication. Without an explicit BAG
retraction notice, higher revision = more recent and more authoritative.

**When to override**: if BAG documentation or a Rundschreiben (circular) in
`data/rundschreiben-archiv.zip` explicitly states that an earlier revision
should be used, update the `is_canonical` column in the manifest manually and
document the reason.

## 7. Transformation Logic

### Step 1 — Source selection
`code/build_manifest.py` scans `data/statistik-ra/`, parses year and revision
from filenames, and marks the highest revision per year as canonical.

### Step 2 — Schema routing
`code/consolidate_ra.py` reads the manifest, loads each canonical workbook with
`openpyxl`, and routes it to the era-specific parser function based on the `era`
column.

### Step 3 — Header normalisation
Each parser locates the data table by searching for known German header keywords
(`Kanton`, `Altersklasse`, `Geschlecht`, `Aufenthalt`, etc.) and renames columns
to stable English identifiers.

### Step 4 — Type coercion
Numeric columns are coerced with `pd.to_numeric(..., errors='coerce')`. Cells
that cannot be parsed become `NaN` and are flagged during validation.

### Step 5 — Provenance stamping
Every output row carries `year`, `revision`, `source_file`, and `source_sheet`
so each data point can be traced back to the exact workbook cell.

### Step 6 — Concatenation and export
All per-year dataframes within each output table are concatenated and written to
CSV in `output/data/`.

## 8. Caveats and Known Limitations

1. **Phase 1 legacy parser not yet implemented.** Workbooks for 1996–2011 use a
   wide-pivoted format (cantons as rows, age-sex groups as columns) that requires
   explicit column mapping. These years are skipped with a warning. Calibration
   note: the simulation's base cost parameters use approximate Swiss averages;
   if precise 1996–2011 cell costs are needed, implement the legacy parser and
   re-run calibration.

2. **PCG column names vary by year.** In Phase 3 workbooks the PCG columns are
   labelled with therapeutic class names in German. The `switzerland_summary`
   table retains these names verbatim. Downstream code must select PCG columns by
   exclusion (drop the fixed dimension columns) rather than by exact name.

3. **Multi-PCG enrollees.** BAG may count individuals in multiple PCG groups; the
   PCG columns in `switzerland_summary` are not mutually exclusive. Do not sum
   PCG month columns to obtain total insured months.

4. **Comorbidity matrix and PCG profile sheet.** Modern workbooks also contain
   `YYYY - PCG` and `YYYY - Komorbiditätsmatrix` sheets. These are profiled in
   `schema_profile.csv` but not yet parsed into separate output tables.

5. **Cost definition.** BAG publishes gross OKP claims costs (before deductibles
   applied to enrollees). Admin costs and supplementary insurance are excluded.
   The `cost_after_ra_chf` (Kobe) column reflects the net cost after RA transfer,
   not after enrollee cost-sharing.

6. **Structural comparability breaks.** Data for 1996–2011 (Phase 1) is not
   directly comparable to later years because the risk cell definitions changed.
   The 2011/2012 and 2019/2020 transitions are hard breaks.

7. **Privacy suppression.** BAG suppresses cells with very few enrollees. These
   appear as blank or zero in the source workbooks and become `NaN` or `0` in
   the output tables. They are not explicitly flagged; treat zero insured-months
   as a likely suppressed cell.

## 9. Validation Rules

Run these checks after each consolidation run:

| Check | Method |
|-------|--------|
| One canonical file per year | `source_manifest.csv`: `is_canonical` count per year == 1 |
| Full year coverage | `source_manifest.csv`: years 1996–2024 all present |
| No duplicate keys in `canton_risk_group` | `groupby(year, source_file, canton, age_band, sex, prior_hospitalisation).size().max() == 1` |
| No null canton | `canton_risk_group.canton.isna().sum() == 0` |
| Annual total cost plausibility | YoY change in `total_cost_chf.sum()` within ±25% |
| Budget neutrality (if RA transfers available) | Sum of `cost_after_ra_chf − total_cost_chf` across cantons ≈ 0 per year |
| PCG column presence in Phase 3 | `switzerland_summary` for year ≥ 2020 has columns beyond the 7 fixed dimensions |

## 10. Refresh Process

When a new BAG annual publication becomes available:

1. Download the new XLSX file and place it in `data/statistik-ra/`.
2. Run `python code/build_manifest.py` to update `output/data/source_manifest.csv`.
3. Check the manifest: confirm that the new file is marked canonical and that
   the era is assigned correctly.
4. If the new year is 2025 or later, inspect the workbook sheets and verify that
   the Phase 3 parser still handles the sheet layout correctly.
5. Run `python code/consolidate_ra.py` to regenerate all output tables.
6. Re-run validation checks from Section 9.
7. Commit the updated manifest and any parser changes. Do not commit raw XLSX
   files or generated CSV output unless explicitly intended for the repository.

## 11. Calibration Link to `code/simulation.py`

The simulation uses the following parameters that should be cross-checked against
the consolidated data:

| Parameter | Simulation value | BAG data reference |
|-----------|------------------|--------------------|
| `BASE_COST` | CHF 3,800 | Annual average cost per insured in `switzerland_summary` for a recent year |
| `BETA_HOSP` | CHF 12,000 | Difference in average cost between `prior_hospitalisation = J` and `N` cells |
| `PCG_COST_EFFECTS` | CHF 900–15,000 per PCG | PCG cost increments from `switzerland_summary` PCG columns |
| `SIGMA_EPSILON` | CHF 5,500 | Residual standard deviation after removing systematic effects |

To recalibrate, compute cell averages from `canton_risk_group.csv` or
`switzerland_summary.csv` for a recent reference year (e.g., 2022 or 2023) and
update the constants at the top of `code/simulation.py`.
